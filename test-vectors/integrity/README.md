Hashes that Python and JavaScript must both reproduce. Owner: Area 3.

Every `*.json` file here is generated by `scripts/make_test_vectors.py` from the real code in `packages/integrity`. Never edit them by hand: a test regenerates them and fails if they differ, and CI runs `uv run python scripts/make_test_vectors.py --check`. After a change to the primitives or the spec, run `uv run python scripts/make_test_vectors.py` and commit the result together with the change (docs/INTEGRITY_SPEC.md section 15).

| File | Covers |
|---|---|
| `sha256.json` | SHA-256 of raw bytes (empty, "abc", two blocks, Hindi, binary) |
| `domain.json` | `domain_hash` for every prefix, export file digests, rejected prefixes |
| `canonical.json` | RFC 8785 canonical JSON, the RFC number table, Hindi and Kannada text, rejected integers |
| `normalize.json` | NFC and line-ending normalisation of string values (keys untouched) |
| `leaves.json` | salted leaves for every salted record type, rejected inputs |
| `merkle.json` | trees of 1 to 17 leaves with every inclusion proof, proof checks (valid and tampered), the empty tree |
| `echo.json` | recap hash to echo code, code normalisation, rejected hash length |
| `chain.json` | a three-version chain and a tampered first version |
| `timestamp.json` | hashed-record timestamps: written form with the offset kept, rejected text and fields (Z, no offset, fractions, `-00:00`, impossible dates) |
| `records.json` | plain records (recap, receipt, import record) |
| `worked_example.json` | the worked example in INTEGRITY_SPEC section 6 |

Checked by `packages/integrity/tests/test_vectors.py`, `scripts/tests/test_make_test_vectors.py` and `apps/verify/tests/integrity.test.mjs`.
